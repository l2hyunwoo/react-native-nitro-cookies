# 기존 앱 마이그레이션

Nitro Cookies는 `@react-native-cookies/cookies`의 익숙한 비동기 쿠키 API를 따릅니다.
import를 바꾼 뒤 앱의 저장소와 플랫폼 전제를 확인하세요.

## 네이티브 의존성 교체

[설치 가이드](../start/installation)에 따라 두 패키지를 설치하고, 기존 네이티브 쿠키 패키지를 제거한 뒤 앱을 다시 빌드하세요.

```diff
- import CookieManager from '@react-native-cookies/cookies';
+ import CookieManager from 'react-native-nitro-cookies';
```

기존 로컬 이름을 유지하면 호출부 변경을 줄일 수 있습니다. 하지만 모든 기존 동작이 같다는 뜻은 아닙니다.

## 기존 전제 확인

| 기존 전제                               | 확인할 내용                                                      |
| --------------------------------------- | ---------------------------------------------------------------- |
| 이름별로 쿠키가 하나뿐이다              | 같은 이름을 보존해야 한다면 Next 목록 API를 사용하세요.          |
| 조회 결과에 원래 범위가 있다            | Android URL 조회로는 복원할 수 없습니다. 저장 범위를 보관하세요. |
| 네이티브와 WebView 쿠키의 저장소가 같다 | 필요한 곳에서 iOS WebKit 저장소를 명시하세요.                    |
| 모든 Android 기기에 쿠키 저장소가 있다  | 정상적인 WebView 제공자가 없는 기기를 처리하세요.                |
| 이름으로 삭제하면 특정 쿠키만 지운다    | 식별자가 겹치면 Next 범위 삭제를 사용하세요.                     |
| 모든 플랫폼에서 모든 메서드를 지원한다  | `getAll`, WebKit, 영속 저장, 세션 동작을 확인하세요.             |

## 동기 메서드는 필요한 곳에 적용

동기 메서드는 Promise를 반환하지 않으며 iOS WebKit 저장소에 접근할 수 없습니다.
WebKit 접근이나 플랫폼 승인 확인이 필요한 곳에서는 비동기 호출을 유지하세요.
동기 메서드가 있다는 이유만으로 모든 비동기 호출을 바꾸지 마세요.

대상 플랫폼에서 인증, 로그아웃, WebView 이동, 영속 저장을 검증하세요.
Next 오류 정규화 계약은 [오류 참조](../reference/errors)에서 확인하세요.
